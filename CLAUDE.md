# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Static marketing site + blog for **Bonhearts Home Care** (Winnipeg, MB), formerly "TrueHeart Home Care".

**Brand name: "Bonhearts Home Care" is the only correct spelling** (short form "Bonhearts", e.g. in the nav or inline). It must match the Google Business Profile, the domain (`bonhearts.ca`) and email exactly. Never write "BonHeart", "Bonheart", "Bon Hearts" or "TrueHeart" in visible text, titles or metadata. The only intentional exceptions: the JSON-LD `alternateName` (`["Bonhearts", "TrueHeart Home Care"]`, which helps Google connect the old name to the new one), the `source: 'trueheart-website'` payload field in `get-in-touch.html` (the Make.com scenario depends on it), and the repo/worker name in `wrangler.jsonc`. The logo wordmark is `Bon<em>hearts</em>`. No build step, no package manager, no dependencies — plain HTML/CSS/JS. Hosted on **GitHub Pages behind Cloudflare** (see **Commands → Deploy**).

## Commands

- **Local dev**: no build step. Open any `.html` file directly, or serve the directory:
  ```
  python3 -m http.server 8000
  ```
- **Deploy / hosting**: the live site is **GitHub Pages behind Cloudflare** (confirmed 2026-10-20: responses carry `x-github-request-id`, `server: cloudflare`, `cache-control: max-age=600`). Pushing to `main` triggers GitHub's "pages build and deployment" run (`gh run list`), live within about a minute; Cloudflare may serve the old copy for up to 10 minutes. Extension-less URLs (`/get-in-touch`, `/guarantee-terms`) work because GitHub Pages serves `foo.html` for `/foo`. `wrangler.jsonc` (Cloudflare Workers static assets) is still in the repo but is **not** what serves the live site — don't run `wrangler deploy` unless the user asks.
- There is no test suite, linter, or build/bundle step in this repo.

## Architecture notes

- **Typography (site-wide since 2026-10-20)**: **Poppins is the site font** — headings, body and buttons — loaded from Google Fonts at weights **400 / 600 / 800 only** (body text 400 at 18px, buttons and bold/`strong` 600, headings 800). **Fraunces 900 is used for the logo wordmark only** (the `.logo` rule, and `.minimal-brand` on `get-in-touch.html`). Public Sans is gone. No `text-transform:uppercase` anywhere — kickers/badges show their text as written. Every page's `<link>` is `family=Fraunces:opsz,wght@9..144,900&family=Poppins:wght@400;600;800`, and every page has `h1,h2,h3{font-family:'Poppins',sans-serif;font-weight:800;...}` plus `strong,th{font-weight:600}`. Use only 400/600/800 in new CSS (other weights get synthesized to the nearest loaded one). Known issue: the desktop nav (901px+) is wider than the window between 901px and ~1210–1290px (worse on blog articles); it already overflowed up to ~1150–1230px with the old fonts.
- **Every HTML file is fully self-contained.** There is no shared CSS/JS file, no templating, no includes. Each page (`index.html` and every blog article) duplicates its own `<style>` block with the same CSS custom properties (`--ink`, `--paper`, `--heart`, `--sage`, etc. — the brand palette) and its own copy of shared behaviors (nav scroll shadow, `IntersectionObserver`-based scroll-reveal, footer markup). **When changing shared visual/behavioral elements (nav, footer, logo, color tokens, reveal animation), the edit must be repeated across all 11 HTML files by hand** — there's no single source of truth to edit once.
- Blog articles share a common internal layout: a `.page-head`, `.toc` (table of contents), `<article>` body with `h2`/`h3`/callouts/`.cta-box`/`.suggest`/tables, all wired to the same scroll-reveal `IntersectionObserver` pattern at the bottom of the file.
